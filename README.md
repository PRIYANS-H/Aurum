# AURUM — MCX Gold Relative-Value Intelligence Platform

> Should I trust this apparent contract-price dislocation, and what evidence supports or weakens that conclusion?

AURUM is a **research and decision-support tool** for MCX gold futures (GOLD, GOLDM, GOLDTEN,
GOLDGUINEA, GOLDPETAL). It checks whether two contracts can be compared at all, puts them on one
verified price basis, measures how unusual their relationship is against its own past (without
look-ahead), records every data-quality and expiry concern, and tests a defined strategy against a
predefined out-of-sample protocol.

It is **not** an arbitrage detector, a gold-price predictor, a trading bot or investment advice.
"No robust edge" and "insufficient evidence" are valid, expected outcomes.

## Setup (Windows / PowerShell; developed and tested on Python 3.14.0)

```powershell
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe -m pytest -q                       # full test suite
```

Not tested on other Python versions; if a dependency fails to install on yours, Python 3.12 is the
first alternative to try.

## Ingesting your MCX data

1. In a browser, download daily bhavcopy **CSV** files from <https://www.mcxindia.com/market-data/bhavcopy>
   (the site blocks automated downloads; respect its terms and do not redistribute the files).
2. Put them in `data/raw/` (git-ignored) and run
   `.\.venv\Scripts\python.exe -m aurum.cli ingest "data/raw/*.csv"` — or upload them on
   Research & Methodology → Data provenance.
3. Each file reports rows read / accepted / rejected (with reasons) / out of scope / already stored.
   Re-downloads are recognised and skipped; conflicting duplicates are rejected, never overwritten.
4. To verify more contract series, download the official spec PDFs from
   <https://www.mcxindia.com/products/bullion/gold>, keep them in `docs/specs/` (git-ignored), and add
   a version to `config/contracts.yaml` with `status: VERIFIED` only for fields you read in the PDF.

## Running

```powershell
.\.venv\Scripts\streamlit.exe run app.py                                     # dashboard, http://localhost:8501
.\.venv\Scripts\python.exe -m aurum.cli analyse --mode REAL --report reports/real.md
.\.venv\Scripts\python.exe -m aurum.cli sample                               # (re)generate SYNTHETIC demo data
```

Restart the dashboard after changing code: Streamlit does not reload the `aurum/` modules, but
cached results are keyed by an engine fingerprint, so they are never reused across engine changes.

## Data modes

| Mode | Meaning |
|---|---|
| HISTORICAL | MCX files you placed in `data/raw` |
| USER_UPLOAD | MCX files uploaded through the dashboard (validated the same way) |
| SYNTHETIC | generated by `aurum/sample_data.py`; mean reversion is built in, so results are **not** evidence. Every page shows a red SYNTHETIC banner |

## Dashboard

1. **Relative Value Explorer** — pick two contracts (rolling rule or fixed expiries), see verified
   normalised prices, spread/carry, z-score and percentile, contract specs with verification status,
   and every flag with its trigger, evidence, effect and confirming data.
2. **Signal Evidence** — queue of statistical alerts with separate alert / validation / conclusion
   statuses; evidence card with source-row identifiers and a recomputation of the z-score; report export.
3. **Backtesting Lab** — feasibility is checked before anything runs; walk-forward folds, final holdout,
   cost scenarios, per-leg trade ledger and the predefined acceptance protocol. Every run is logged.
4. **Research & Methodology** — provenance and cross-file integrity, spec and pair registries,
   formulas, flag and protocol rules, cost-rate sources, live checks, test runner, research log.

## Layout

```
app.py                  dashboard shell (sidebar, data bar, routing)
aurum/ingestion.py      parse, validate, reject log, provenance, conflict detection, Parquet store
aurum/contracts.py      versioned specs, comparability rules, normalisation, multiplier cross-check
aurum/analytics.py      pair series, measures, look-ahead-free statistics, flag registry
aurum/signals.py        the single classification vocabulary and rules
aurum/backtest.py       execution model, costs, per-leg accounting, fold plan, walk-forward
aurum/validation.py     feasibility, cost stress, integrity checks, acceptance protocol
aurum/pipeline.py       orchestration, evidence card, Markdown report, experiment log
aurum/ui/               theme, components, session state, four pages
config/                 contracts.yaml, pairs.yaml, research.yaml (all assumptions, with sources)
docs/                   methodology, limitations, data dictionary, research log
tests/                  pytest suite (engine, protocol, ingestion, UI integration)
```
